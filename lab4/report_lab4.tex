\subsection{Problema comenzii \texttt{cd}}
\begin{enumerate}
    \item \textbf{De ce \texttt{cd} nu poate fi un program separat (cum este \texttt{ls})?} 
    Pentru a executa un program separat, shell-ul folosește apelul \texttt{fork()} pentru a crea un proces copil, iar copilul folosește \texttt{exec()} pentru a rula programul. Dacă \texttt{cd} ar fi un program separat, procesul copil ar fi cel care și-ar schimba directorul de lucru. Imediat ce copilul și-ar termina execuția, shell-ul (procesul părinte) ar rămâne în exact același director ca înainte. Pentru ca shell-ul să își schimbe \textit{propriul} director, \texttt{cd} trebuie să fie o comandă nativă (\textbf{built-in}) scrisă direct în codul sursă al shell-ului (apelând \texttt{chdir()} în procesul curent).
    
    \item \textbf{Soluția pentru rularea succesivă:} Dacă vrem să listăm fișierele dintr-un folder folosind xv6 fără a ne muta definitiv în el, putem transmite calea direct programului: \texttt{ls d}.
\end{enumerate}

\section{Concluzii}
Interfața unui sistem de operare dictează limitările mediului său. În timp ce Bash pe Linux este un program masiv cu capabilități de limbaj de programare (bucles, funcții), shell-ul din xv6 este doar o mască subțire peste apelurile de sistem, ilustrând perfect mecanica nudă a sistemelor de tip UNIX (motivul tehnic imperios pentru care funcții precum \texttt{cd} trebuie implementate intern).
