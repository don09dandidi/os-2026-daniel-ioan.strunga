\subsection*{Observe (Part 2)}
\begin{enumerate}
\Q{1. List the features both shells have, and the ones only bash has.}
{\textbf{Ambele:} rularea programelor (\texttt{fork} + \texttt{exec} + \texttt{wait}), redirectările \texttt{<}, \texttt{>} (și \texttt{>>}), pipe-urile \texttt{|}, secvența \texttt{;}, gruparea cu \texttt{( )}, fundalul \texttt{\&} și built-in-ul \texttt{cd} (doar ca primă comandă din linie, în xv6).\\
\textbf{Doar bash:} globbing (\texttt{*}, \texttt{?}, \texttt{[ ]}), variabile și expansiuni (\texttt{\$HOME}, \texttt{\$(...)}, \texttt{\$((...))}, \texttt{\{1..5\}}), ghilimele și backslash, căutarea în \texttt{PATH}, \texttt{\&\&} și \texttt{||}, \texttt{2>\&1}, job control (\texttt{jobs}, \texttt{kill \%1}, \texttt{Done}), istoric (săgeți, Ctrl+R), completare cu Tab, \texttt{cd} oriunde în linie, coduri de ieșire (\texttt{\$?}) și scripturi.}
\Q{2. In xv6, ls stops working after cd d. Why? Find a way to run ls from inside d anyway.}
{xv6 \textbf{nu are \texttt{PATH}}. Shell-ul apelează \texttt{exec("ls", argv)}, iar kernelul caută fișierul \texttt{ls} relativ la directorul curent. Toate programele xv6 se află în rădăcina \texttt{/} (au fost puse acolo de \texttt{mkfs} din \texttt{UPROGS}). Cât timp directorul curent este \texttt{/}, \texttt{ls} se găsește; în \texttt{d} nu există niciun fișier \texttt{ls}, deci \texttt{exec ls failed}.\\
\textbf{Soluția}, în figura 2.3: calea absolută \texttt{/ls} (la fel \texttt{/cat}, \texttt{/echo} etc.), de exemplu \texttt{/ls} sau \texttt{/ls ..}. A doua variantă este revenirea în rădăcină cu \texttt{cd /} sau \texttt{cd ..}, după care \texttt{ls} funcționează din nou.}
\Q{3. Which missing feature would you miss most in daily work, and which would be easiest to add?}
{\textbf{Cel mai mult mi-ar lipsi} istoricul cu săgeți și completarea cu Tab, plus globbing-ul: fără ele trebuie rescrisă fiecare comandă și fiecare nume de fișier.\\
\textbf{Cel mai ușor de adăugat} este un \texttt{PATH} minimal. În \texttt{runcmd}, cazul \texttt{EXEC}: dacă \texttt{exec(argv[0])} eșuează și numele nu conține \texttt{/}, se încearcă din nou cu \texttt{"/"} pus în față. Sunt câteva linii de cod, iar problema \texttt{exec ls failed} dispare. Ar fi simple și \texttt{\&\&} / \texttt{||}, pentru că \texttt{wait()} întoarce deja codul de ieșire al copilului.}
\end{enumerate}

\subsection*{Observe (Part 3)}
\begin{enumerate}
\Q{1. Paste both outputs for args *.c "x y". How many arguments did each program receive?}
{Output-urile sunt în figurile 3.2 și 3.3.
\begin{itemize}
  \item \textbf{bash/Linux:} \texttt{argc = 5}, adică numele programului plus \textbf{4 argumente}: \texttt{a.c}, \texttt{args\_linux.c}, \texttt{b.c} și \texttt{x y} (un singur argument, cu spațiu, fără ghilimele).
  \item \textbf{xv6:} \texttt{argc = 4}, adică numele programului plus \textbf{3 argumente}: \texttt{*.c} literal, \texttt{"x} și \texttt{y"} (ghilimelele au rămas, iar textul a fost tăiat la spațiu).
\end{itemize}}
\Q{2. So who turns *.c into file names and removes the quotes: the program, the kernel, or the shell?}
{\textbf{Shell-ul.} Programul este identic pe ambele sisteme și doar afișează ce primește; kernelul (\texttt{exec}) doar copiază vectorul \texttt{argv} primit în memoria noului proces. Diferența vine din shell: bash face globbing și elimină ghilimelele \emph{înainte} de \texttt{exec}, iar shell-ul xv6 doar împarte linia la spații.}
\Q{3. What happened to the extra spaces in one two three?}
{Au dispărut în ambele shell-uri: \texttt{argc = 4}, cu argumentele \texttt{one}, \texttt{two}, \texttt{three}. Spațiile sunt doar separatori. Shell-ul sare peste orice șir de spații consecutive (în xv6, bucla din \texttt{gettoken} sare peste caracterele din \texttt{whitespace[]}), deci programul nu află câte spații au fost. Pentru a păstra spațiile, în bash argumentul trebuie pus între ghilimele (\texttt{"one   two"}); în xv6 nu se poate.}
\end{enumerate}

\begin{shot}{4.3}{Codul care tratează cd}
\begin{lstlisting}[language=C]
$ grep -n "cd" user/sh.c | head
170:        fprintf(2, "cannot cd %s\n", cmd + 3);

  // din main():
  while (getcmd(buf, sizeof(buf)) >= 0) {
    char *cmd = buf;
    while (*cmd == ' ' || *cmd == '\t')
      cmd++;
    if (*cmd == '\n') // is a blank command
      continue;
    if (cmd[0] == 'c' && cmd[1] == 'd' && cmd[2] == ' ') {
      // Chdir must be called by the parent, not the child.
      cmd[strlen(cmd) - 1] = 0; // chop \n
      if (chdir(cmd + 3) < 0)
        fprintf(2, "cannot cd %s\n", cmd + 3);
    } else {
      if (fork1() == 0)
        runcmd(parsecmd(cmd));
      wait(0);
    }
  }
\end{lstlisting}
\end{shot}

\subsection*{Observe (Part 4)}
\begin{enumerate}
\Q{1. Name the five kinds of command the xv6 shell knows and the character that produces each.}
{\begin{itemize}
  \item \texttt{EXEC} (1) -- o comandă simplă: cuvinte despărțite prin spații, fără caracter special (de exemplu \texttt{ls -l}); rulată cu \texttt{exec()}.
  \item \texttt{REDIR} (2) -- \texttt{<}, \texttt{>} și \texttt{>>} (intern \texttt{'+'}); închide fd 0 sau 1 și deschide fișierul în locul lui.
  \item \texttt{PIPE} (3) -- \texttt{|}; \texttt{pipe()} plus două procese copil, cu capetele legate la fd 1 și fd 0.
  \item \texttt{LIST} (4) -- \texttt{;}; rulează stânga, așteaptă (\texttt{wait}), apoi dreapta.
  \item \texttt{BACK} (5) -- \texttt{\&}; rulează comanda într-un copil fără să o aștepte.
\end{itemize}
Parantezele \texttt{( )} nu formează un tip separat: \texttt{parseblock} le transformă în subarborele dintre ele. Setul complet de simboluri este \texttt{symbols[] = "<|>\&;()"} (linia 269).}
\Q{2. Where is cd handled, and why is it not run as a separate program?}
{\texttt{cd} este tratat direct în \texttt{main()} din \texttt{sh.c} (figura 4.3, linia 170 pentru mesajul de eroare). Dacă linia începe cu \texttt{"cd "}, shell-ul apelează \texttt{chdir(cmd + 3)} în propriul proces, \emph{fără} \texttt{fork}. Comentariul din cod spune exact: \emph{„Chdir must be called by the parent, not the child.”}\\
Directorul curent este o proprietate a procesului (\texttt{p->cwd} în kernel). Un program \texttt{cd} separat ar rula într-un copil creat cu \texttt{fork}, și-ar schimba propriul director și s-ar termina, iar shell-ul ar rămâne unde era.\\
Consecința se vede în Part 2: \texttt{cd} funcționează doar la începutul liniei. În \texttt{mkdir d ; cd d ; ls ..}, linia începe cu \texttt{mkdir}, deci \texttt{cd} ajunge în \texttt{runcmd} ca \texttt{EXEC} și dă \texttt{exec cd failed}. Iar \texttt{cd d; ls} ar apela \texttt{chdir("d; ls")} și ar afișa \texttt{cannot cd d; ls}.}
\item \textbf{3. Search sh.c for any code that handles * or \$. What does that explain about Part 2?}\\
Nu există niciun astfel de cod:
\begin{lstlisting}[language=bash]
$ grep -n "'\*'\|'\$'\|glob" user/sh.c
$ echo $?
1
$ grep -n "symbols\[\]\|whitespace\[\]" user/sh.c
268:char whitespace[] = " \t\r\n\v";
269:char symbols[] = "<|>&;()";
\end{lstlisting}
Singurele caractere speciale sunt cele din \texttt{symbols[]} și spațiile din \texttt{whitespace[]}. \texttt{*}, \texttt{\$} și ghilimelele sunt pentru shell-ul xv6 litere obișnuite, care fac parte din cuvânt. Asta explică rezultatele din Part 2 și Part 3: \texttt{ls *} dă \texttt{cannot open *}, \texttt{echo \$HOME} afișează \texttt{\$HOME}, \texttt{echo "a b"} afișează ghilimelele, iar \texttt{args *.c "x y"} primește \texttt{*.c}, \texttt{"x} și \texttt{y"}. Toate aceste funcții există în bash doar pentru că bash are cod care le face.
\end{enumerate}

\section*{Concluzii}
Un shell minimal are nevoie de puțin: citește o linie, o împarte în cuvinte, construiește un arbore din cinci tipuri de comenzi (\texttt{EXEC}, \texttt{REDIR}, \texttt{PIPE}, \texttt{LIST}, \texttt{BACK}) și îl execută cu \texttt{fork}, \texttt{exec}, \texttt{wait}, \texttt{pipe}, \texttt{open}/\texttt{close}. Tot ce face bash peste acest minim (globbing, variabile, ghilimele, \texttt{PATH}, \texttt{\&\&}/\texttt{||}, istoric, completare, job control) este cod suplimentar în shell, nu în kernel și nici în programe. Programul \texttt{args} arată asta direct: același cod primește argumente diferite în funcție de shell. \texttt{cd} trebuie să fie în shell, pentru că schimbă starea procesului shell. Lipsa \texttt{PATH} din xv6 explică de ce \texttt{ls} nu mai merge după \texttt{cd d} și de ce soluția este \texttt{/ls}. Programul \texttt{sleep} a fost adaptat la redenumirea \texttt{sleep()} $\rightarrow$ \texttt{pause()} și rulează corect pe xv6-ul actual.
