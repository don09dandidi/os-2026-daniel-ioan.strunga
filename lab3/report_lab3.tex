\section{Part 1. Move fast, find help}

\textbf{Tab.} La \texttt{ls /usr/sh} + Tab Tab shell-ul a completat singura variantă posibilă, \texttt{/usr/share/}; dacă ar fi existat mai multe potriviri, al doilea Tab le-ar fi listat pe toate. La \texttt{cd /et} + Tab a completat direct \texttt{/etc/}, fiind o singură potrivire. Lista de candidați pe care o folosește Tab se poate afișa cu \texttt{compgen}:
\begin{shot}{1.1}{Tab completion (candidații oferiți de Tab)}
\begin{lstlisting}[language=bash]
$ compgen -f /usr/sh      # ce ofera Tab Tab dupa "ls /usr/sh"
/usr/share
$ compgen -d /et          # ce completeaza Tab dupa "cd /et"
/etc
\end{lstlisting}
\end{shot}

\textbf{Ctrl+R.} După trei comenzi oarecare (de exemplu \texttt{date}, \texttt{whoami}, \texttt{pwd}), Ctrl+R deschide promptul \texttt{(reverse-i-search)}. La primele litere ale primei comenzi (\texttt{da}), bash găsește cea mai recentă comandă din istoric care le conține (\texttt{date}), iar Enter o rulează din nou. Ctrl+R caută deci înapoi în istoricul comenzilor (\texttt{\textasciitilde/.bash\_history}).

\subsection*{Observe (Part 1)}
\begin{enumerate}
\Q{1. Which of cd, ls, echo are built-ins, and why MUST cd be one?}
{\texttt{cd} și \texttt{echo} sunt built-in (\texttt{shell builtin}); \texttt{ls} este un program extern, \texttt{/usr/bin/ls} (în bash interactiv este și alias pentru \texttt{ls --color=auto}). \texttt{cd} trebuie să fie built-in pentru că directorul curent este un atribut al fiecărui proces. Un program extern ar rula într-un proces copil (\texttt{fork} + \texttt{exec}) și ar schimba doar directorul copilului, care se termină imediat; shell-ul ar rămâne în același director. De aceea shell-ul apelează \texttt{chdir()} chiar în procesul său.}
\Q{2. How many directories are in your PATH, and in which one is ls?}
{În \texttt{PATH} sunt \textbf{9} directoare (figura 1.3). \texttt{ls} se află în \texttt{/usr/bin} (\texttt{which ls} $\rightarrow$ \texttt{/usr/bin/ls}). Shell-ul caută comanda în directoarele din \texttt{PATH}, în ordine, și o rulează pe prima găsită.}
\Q{3. What exit code does a command that is not found return?}
{\textbf{127} (figura 1.4). Prin convenție, 127 înseamnă „command not found”, iar 126 „găsită, dar nu se poate executa”.}
\Q{4. Which option of ls sorts by modification time? (find it in man ls)}
{Opțiunea \textbf{\texttt{-t}}: \emph{„sort by time, newest first”} (figura 1.5); cele mai noi fișiere apar primele. Cu \texttt{-r} ordinea se inversează (\texttt{ls -tr}: cele mai vechi primele).}
\end{enumerate}

\subsection*{Observe (Part 2)}
\begin{enumerate}
\Q{1. For each line: your prediction, the real output, and one sentence if they differ.}
{Vezi tabelul de mai sus. Au fost două diferențe: \texttt{[a-b]*} a prins și \texttt{alfa beta.txt}, iar \texttt{*.xyz} fără potrivire rămâne literal.}
\Q{2. echo knows nothing about files, yet echo *.c printed file names. Who produced them?}
{\textbf{Shell-ul.} Înainte să pornească programul, bash face \emph{pathname expansion} (globbing): înlocuiește \texttt{*.c} cu lista fișierelor din director care se potrivesc. \texttt{echo} primește deja argumentele \texttt{a.c} și \texttt{b.c} și doar le afișează; nu vede niciodată caracterul \texttt{*}.}
\Q{3. Why did ls alfa beta.txt fail? Give two different ways to fix it.}
{Shell-ul împarte linia în cuvinte la spații, deci \texttt{ls} a primit două argumente, \texttt{alfa} și \texttt{beta.txt}, iar niciunul nu există. Corectări (figura 2.3): (1) ghilimele, \texttt{ls "alfa beta.txt"} (sau \texttt{'alfa beta.txt'}); (2) escaparea spațiului cu backslash, \texttt{ls alfa\textbackslash{} beta.txt}. O a treia variantă este Tab: \texttt{ls alf}+Tab scrie singur \texttt{alfa\textbackslash{} beta.txt}.}
\Q{4. What is the difference between single and double quotes? (and why ls shows 'alfa beta.txt' in quotes)}
{Între \textbf{ghilimele simple} totul este literal: nu se expandează nimic (\texttt{'\$HOME'} $\rightarrow$ \texttt{\$HOME}). Între \textbf{ghilimele duble} se fac în continuare expansiunile cu \texttt{\$}: variabile (\texttt{"\$HOME"} $\rightarrow$ \texttt{/home/user}), \texttt{\$(...)} și \texttt{\$((...))}. Se opresc însă globbing-ul și împărțirea în cuvinte. Backslash-ul (\texttt{\textbackslash{}\$HOME}) face literal doar caracterul următor.\\
\texttt{ls} afișează \texttt{'alfa beta.txt'} între apostrofuri pentru că, atunci când scrie într-un terminal, GNU \texttt{ls} folosește implicit \texttt{--quoting-style=shell-escape}. Astfel numele afișat poate fi copiat direct într-o comandă și rămâne un singur argument. Când ieșirea merge într-un pipe sau fișier, apostrofurile nu mai apar (\texttt{ls | cat} afișează \texttt{alfa beta.txt}).}
\end{enumerate}

\section{Part 3. Redirection, chaining and jobs}

\begin{shot}{3.1}{stdout și stderr în fișiere separate}
\begin{lstlisting}[language=bash]
$ cd ~/os-lab3
$ ls /etc /nope > out.txt 2> err.txt
$ wc -l out.txt ; cat err.txt
250 out.txt
ls: cannot access '/nope': No such file or directory
$ ls /etc /nope > all.txt 2>&1 ; tail -2 all.txt
xml
zsh_command_not_found
$ echo first > notes.md ; echo second >> notes.md ; cat notes.md
first
second
$ wc -l < access.log
500
$ wc -l access.log
500 access.log
\end{lstlisting}
\end{shot}

\begin{shot}{3.2}{Compararea ordinii redirectărilor}
\begin{lstlisting}[language=bash]
$ ls /etc /nope > all.txt 2>&1 ; grep -c nope all.txt
1
$ ls /etc /nope 2>&1 > all.txt ; grep -c nope all.txt
ls: cannot access '/nope': No such file or directory
0
\end{lstlisting}
\end{shot}

\begin{shot}{3.3}{Operatorii ; \&\& ||}
\begin{lstlisting}[language=bash]
$ ls /nope 2> /dev/null || echo "failed with code $?"
failed with code 2
$ mkdir -p tmp && cd tmp && echo "I am in $(pwd)" ; cd ~/os-lab3
I am in /home/user/os-lab3/tmp
$ true && echo "and: runs"; false && echo "and: skipped"; false || echo "or: runs"; false ; echo "semicolon: always"
and: runs
or: runs
semicolon: always
\end{lstlisting}
\end{shot}

\begin{shot}{3.4}{Pornirea unui job în fundal și oprirea lui}
\begin{lstlisting}[language=bash]
$ sleep 100 &
$ jobs ; kill %1 ; jobs
[1]+  Running                 sleep 100 &
[1]+  Terminated              sleep 100
\end{lstlisting}
\end{shot}

\subsection*{Observe (Part 3)}
\begin{enumerate}
\Q{1. Which file got the error message, and which got the listing?}
{Mesajul de eroare (\texttt{cannot access '/nope'}) a ajuns în \texttt{err.txt}, prin \texttt{2>}, adică descriptorul 2, stderr. Lista din \texttt{/etc} (250 de linii) a ajuns în \texttt{out.txt}, prin \texttt{>}, adică descriptorul 1, stdout. Cu \texttt{> all.txt 2>\&1} ambele ajung în \texttt{all.txt}.}
\Q{2. What is the difference between > all.txt 2>\&1 and 2>\&1 > all.txt? Try both and explain why the result differs.}
{Redirectările se aplică \textbf{de la stânga la dreapta}, iar \texttt{2>\&1} înseamnă „fă ca fd 2 să arate unde arată fd 1 \emph{acum}”, nu „pentru totdeauna”.
\begin{itemize}
  \item \texttt{> all.txt 2>\&1}: întâi stdout trece în \texttt{all.txt}, apoi stderr îl copiază, deci și eroarea ajunge în fișier (\texttt{grep -c nope} $\rightarrow$ 1).
  \item \texttt{2>\&1 > all.txt}: întâi stderr copiază stdout-ul de atunci (terminalul), apoi doar stdout e mutat în fișier. Eroarea apare pe ecran, iar în fișier nu e (\texttt{grep -c nope} $\rightarrow$ 0), ca în figura 3.2.
\end{itemize}}
\Q{3. Why does wc -l < access.log print only a number, while wc -l access.log also prints the file name?}
{La \texttt{wc -l < access.log} fișierul îl deschide \textbf{shell-ul} și îl leagă la stdin-ul lui \texttt{wc}; \texttt{wc} nu primește niciun argument, citește din stdin și nu cunoaște numele fișierului, deci afișează doar \texttt{500}. La \texttt{wc -l access.log} numele este argument, \texttt{wc} deschide singur fișierul și îl afișează lângă număr: \texttt{500 access.log}.}
\Q{4. Explain each operator in one sentence: ; \&\& ||.}
{\begin{itemize}
  \item \texttt{;} rulează comenzile una după alta, indiferent dacă prima a reușit sau nu.
  \item \texttt{\&\&} rulează comanda din dreapta doar dacă cea din stânga a reușit (cod de ieșire 0).
  \item \texttt{||} rulează comanda din dreapta doar dacă cea din stânga a eșuat (cod diferit de 0); de exemplu \texttt{failed with code 2} în figura 3.3.
\end{itemize}}
\end{enumerate}

\begin{lstlisting}[language=bash]

\end{shot}
\textbf{Q4. Which user or users have the most failed requests, and how many?} \textbf{user3 și user5}, la egalitate, cu câte \textbf{15} eșecuri. Un simplu \texttt{head -1} ar fi afișat doar unul dintre ei și ar fi ascuns egalitatea; \texttt{awk} reține valoarea maximă din prima linie (\texttt{m}) și afișează toate liniile cu aceeași valoare. Verificare: $14+14+14+15+14+15+14 = 100$, egal cu Q1 (figura 5.2).

\begin{shot}{4.5}{Q5 -- Cererile lui user3}
\begin{lstlisting}[language=bash]

\end{shot}
\textbf{Q5. How many requests did user3 make, and how many of them failed?} \textbf{72} de cereri, din care \textbf{15} eșuate. Spațiile din \texttt{' user3 '} asigură potrivirea exactă a câmpului.

\begin{shot}{4.8}{Q8 -- Diferența dintre ls /etc și ls -l /etc}
\begin{lstlisting}[language=bash]
# Q8. Why do ls /etc | wc -l and ls -l /etc | wc -l differ by exactly one?
$ ls /etc | wc -l ; ls -l /etc | wc -l
249
250
$ ls -l /etc | head -1
total 1272
\end{lstlisting}
\end{shot}
\textbf{Q8. PREDICT, then explain: why do ls /etc | wc -l and ls -l /etc | wc -l differ by exactly one?} \emph{Predicție:} \texttt{ls -l} are în plus o linie de antet. \emph{Rezultat:} 249 față de 250. Diferența este prima linie a lui \texttt{ls -l}, \texttt{total 1272} (numărul total de blocuri ocupate), care nu e un fișier. În rest ambele comenzi afișează câte o linie pe intrare: când ieșirea este un pipe, \texttt{ls} scrie un nume pe linie, nu în coloane.

\subsection*{Observe (Part 5)}
\begin{enumerate}
\Q{1. What does the first line \#!/bin/bash do, and what happens if you run ./report.sh before chmod +x?}
{\texttt{\#!/bin/bash} este \emph{shebang}-ul. La \texttt{exec}, kernelul vede că fișierul începe cu octeții \texttt{\#!} și pornește programul indicat, \texttt{/bin/bash}, cu calea scriptului ca argument. Așa știe sistemul că fișierul se rulează cu bash, nu cu alt interpretor.\\
Înainte de \texttt{chmod +x}, fișierul are permisiunile \texttt{-rw-r--r--}, fără bitul de execuție. \texttt{./report.sh} dă \texttt{Permission denied}, cu codul de ieșire \textbf{126}: fișierul există, dar \texttt{execve()} refuză să-l execute. După \texttt{chmod +x} permisiunile devin \texttt{-rwxr-xr-x} și scriptul rulează (figura 5.2). Fără \texttt{chmod}, scriptul se poate rula doar cu \texttt{bash report.sh}, caz în care bash doar îl citește.}
\Q{2. Why must you type ./report.sh and not just report.sh?}
{Un nume fără \texttt{/} este căutat \textbf{doar în directoarele din \texttt{PATH}} (figura 1.3), iar directorul curent (\texttt{\textasciitilde/os-lab3}) nu este în \texttt{PATH}. De aceea \texttt{report.sh} dă \texttt{command not found} (127, figura 5.3). \texttt{./report.sh} este o cale explicită către fișierul din directorul curent, deci shell-ul nu mai caută în \texttt{PATH}. Directorul curent nu se pune în \texttt{PATH} din motive de siguranță: altfel un fișier numit \texttt{ls} dintr-un director străin ar putea fi rulat în locul programului real.}
\Q{3. Why does the script write the error with >\&2 and end with exit 1?}
{\texttt{>\&2} trimite mesajul pe \textbf{stderr}, nu pe stdout. Astfel eroarea apare pe ecran chiar dacă rezultatul scriptului e redirectat într-un fișier sau pipe (\texttt{./report.sh x.log > r.txt}), și nu ajunge amestecată cu datele. \texttt{exit 1} întoarce un \textbf{cod de ieșire diferit de 0}, adică „eșec”. Așa \texttt{\&\&}, \texttt{||}, \texttt{if} sau \texttt{cron} pot afla că scriptul nu a reușit: de exemplu \texttt{./report.sh nope.log || echo eroare}. Cu \texttt{exit 0}, sau fără \texttt{exit}, eroarea ar trece neobservată.}
\end{enumerate}

\section*{Concluzii}
Shell-ul transformă linia înainte ca programul să pornească: face globbing (\texttt{*.c}), elimină ghilimelele, expandează variabilele și \texttt{\$(...)} și împarte linia în cuvinte. Programul primește doar rezultatul. Din acest motiv \texttt{echo *.c} afișează fișiere, iar \texttt{ls alfa beta.txt} eșuează. Redirectările se aplică de la stânga la dreapta, iar ordinea lui \texttt{2>\&1} schimbă rezultatul. \texttt{;}, \texttt{\&\&} și \texttt{||} folosesc codul de ieșire al comenzii anterioare. Filtrele mici (\texttt{grep}, \texttt{cut}, \texttt{sort}, \texttt{uniq}, \texttt{wc}) legate prin pipe-uri au răspuns la toate cele opt întrebări despre log, iar verificările (Q3 = 500, suma eșecurilor = Q1) confirmă că pipeline-urile filtrează ce trebuie. Scriptul \texttt{report.sh} arată ce face un script corect: shebang, bit de execuție, erori pe stderr și cod de ieșire diferit de 0 la eșec.
